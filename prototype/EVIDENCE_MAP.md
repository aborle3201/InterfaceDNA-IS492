# InterfaceDNA Prototype Evidence Map

This file helps trace major prototype choices back to Checkpoint 2 validation evidence and the human–AI complementarity lens.

| Prototype element | Validation receipt / finding | Complementarity reading | Design principle |
|---|---|---|---|
| Verified context stage | T03 and T04 still required students to gather records or navigate systems | Human attention is wasted when the student becomes the integration layer | Knowledge infrastructure + attention orchestration |
| Policy source/version card | F01 reached a safe conclusion but introduced irrelevant/unreliable context | Model memory/retrieval should not be treated as institutional memory | Knowledge infrastructure |
| “I’m not sure” policy-conflict state | E02 correctly identified an unresolved conflict | The hybrid must expose disagreement and escalate instead of manufacturing certainty | Meta-coordination + trust calibration |
| Missing-record failure state | Graduation advice depends on an authoritative degree audit/catalog match | Missing institutional memory should remain visible rather than be filled with model assumptions | Memory + interrogation |
| University service outage state | Verified context may be temporarily unavailable | A safe hybrid should stop when the AI’s supporting infrastructure is unavailable | Goals/constraints + escalation |
| “Why?” panels | Interviews emphasized accuracy/reliability and concise consequence explanations | Students need lightweight interrogation without reading a full chain of reasoning | Attention + interrogation orchestration |
| Consequence summary | Course-drop prompts showed AI can reason but often leaves applicability to the student | AI should organize dependencies while the student evaluates trade-offs | Reasoning + role partitioning |
| Confirmation gates | F03 refused false execution and interviews required confirmation before permanent actions | Final decision rights belong to the human | Meta-coordination + role partitioning |
| No false success state | F03 distinguished advice from actually performing the drop | System state and action state must remain truthful | Trust calibration |
| Office-specific hold routing | T04 still required portal/email/office navigation | AI should coordinate next steps but respect organizational ownership | Attention + meta-coordination |
